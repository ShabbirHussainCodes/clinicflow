# Technical decisions

1. **Browser never talks to Supabase.** Server Components/Actions only. Removes key exposure, makes CSP `connect-src 'self'`, allows runtime env (no `NEXT_PUBLIC_`). Trade-off: no realtime/client SDK features.
2. **Business rules in PostgreSQL** (slots, booking, transitions, search) as functions; the app is a thin typed layer. One source of truth, testable with plain SQL, enforced for every client. Trade-off: SQL is harder to refactor than TS.
3. **Exclusion constraint + advisory lock + recheck** for double booking. The constraint is the guarantee; the lock makes the function deterministic.
4. **Appointment length = service duration rounded up to the doctor's slot grid** so the grid stays aligned and a long service blocks the neighbouring slots.
5. **Date and time share one wizard step** (brief lists them separately): the time grid appears under the calendar; fewer clicks, same information.
6. **Booking reference** `CF-XXXXX-XXXXX`, 32-symbol alphabet (no I/O), 50 bits from `gen_random_uuid()` (no pgcrypto), plus lookup rate limits. Confirmation shows masked contact data.
7. **Admin via RPC + RLS, not service role.** Admins act with their own JWT; the service key is used only by the dispatcher and `create-admin`.
8. **Outbox + dispatcher** instead of calling n8n from the booking path; at-least-once, HMAC signing, optional static token. Scheduling is left to the owner because Render's free tier has no cron.
9. **In-memory rate limiting** (documented limitation) plus database per-phone cap.
10. **Sign-up disabled, email provider enabled.** `[auth.email] enable_signup=false` would also disable password login (`email_provider_disabled`); the correct switch is `[auth] enable_signup=false`.
11. **HttpOnly session cookies, 7-day cap** (`src/lib/supabase/cookies.ts`), possible because no browser Supabase client exists.
12. **Nonce CSP in `proxy.ts`** (forces dynamic rendering, which the app needs anyway). Dev relaxes `style-src` for HMR.
13. **Phone matching in admin search only for phone-like queries** (found by a flaky test: digits inside text matched unrelated numbers).
14. **Fonts local**: Source Serif 4 and Source Sans 3 (Latin subset, weight axis only, about 80 KB) copied into `src/assets/fonts` (no build-time Google Fonts fetch). They replaced Fraunces and Figtree, which read as a generic start-up look.
15. **`agentRules: false`**: `next dev` otherwise rewrites the owner's `CLAUDE.md`.
16. **Tests use real Postgres, not mocks**; Playwright runs against a production build so CSP/caching are real.
17. **Cloud-sandbox only**: Docker Hub mirror via `SUPABASE_INTERNAL_IMAGE_REGISTRY=docker.io` because `ghcr.io` blobs were blocked by egress policy. Not needed on normal machines.
18. **The public site carries the clinic's identity; ClinicFlow stays in the staff area.** The brief asks for a ClinicFlow logo (kept in the dashboard, sign-in page and `LogoMark`). The owner later asked to hand the site to real clients by changing information, so the header, footer, favicon and titles show the clinic (its logo from `public/brand`, or a monogram and the name). The footer credit "Online booking by ClinicFlow" is configurable (`credit: null` removes it).
19. **Editorial redesign instead of illustrations.** Owner feedback: the first design looked unprofessional and AI-made. The arches, faceless doctors, hero scene, floating UI cards, icon tiles, gradient circles and the fake map sketch were removed. Replaced by typography, ruled lists, real computed facts, a live availability panel and photograph slots. Rule of thumb: no decoration that carries no information.
20. **Wording in `src/config/site.ts`, clinic data in the database.** No CMS (free tiers, no extra service). The file is typed, supports `{clinic}`-style placeholders, hides sections when empty, and a unit test catches misspelled placeholders. Trade-off: changing text needs code access until the staff-area editor exists (see `NEXT_STEPS.md`).
21. **Photographs by file-name convention in `public/`** (`doctors/<slug>`, `clinic/hero|about|map`, `brand/logo`). Found on the server with `fs`; names are validated against `^[a-z0-9-]+$` so a database value can never traverse paths; lookups are cached only in production. Verified with the Next.js image optimizer on a production server. Trade-off: pictures ship with the deployment; runtime upload (Supabase Storage) is a later step.
22. **Doctor cards adapt to the photographs available.** If no doctor has a photo the page shows a compact ruled directory with initials badges (finished, not a row of empty frames); if any has one, all cards use 4:5 portraits.
23. **Clinic hours are the union of the doctors' windows**, not "earliest start to latest end". The earlier summary promised hours nobody worked (for example 9:00 AM to 7:40 PM across a mid-afternoon gap). "Open now" is computed in the clinic's own time zone and treats clinic-wide holidays as closed (`src/lib/open-status.ts`).
24. **Colour tokens renamed `teal-*` to `brand-*`** so re-branding does not leave a misleading name; the dashboard chart uses token classes instead of hex values, so it follows the brand colour too.
25. **Next free times are read live on every home page request** (no cache), from the same functions the booking form uses, for up to four doctors in parallel. The page can therefore never show a time the booking form would not offer; a link whose time has since been taken is explained by the booking page.
